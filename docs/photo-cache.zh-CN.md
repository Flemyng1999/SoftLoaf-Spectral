# 图像缓存与 RAW 两阶段开发

2026-10-28，Issue #9。当前实现沿用 AppKit/WebKit、RT 和 Metal；参考
[AlcedoStudio 18c86370](https://github.com/zidage/AlcedoStudio/tree/18c863702565e4be7cba5d889314b555b6fb6037)
的 thumbnail service、thumbnail disk cache 和 RAW input loader。
借鉴的是分层数据、版本键、并发去重、后台读取、有限解码名额和过期结果保护，
没有复制其代码，也没有引入 Qt 框架。

## 项目约束

对同一不可变 RAW 和固定相机校准，应用只做两个开发阶段：

1. 导入时一次 half-size 开发，供原图、胶片预览、缩略图和后续预取使用。
2. 第一次完整尺寸导出时一次完整开发，此后导出继续使用保留的浮点数据。

每个阶段只启动一个 RT 开发进程。Bayer 的 sRGB D65 和线性 ACEScg AP1/D60
由同一次解码、黑电平校正、白平衡和 DCP 处理后的 Lab 数据分别通过输出 ICC
生成，均为 float32 TIFF。没有先转展示用的 sRGB 再进入胶片计算。
导出的 LUT 仍消费 ACEScct AP1/D60。

四像元缩小仅适用于已验证的普通三色 Bayer。X-Trans 保留官方 RT 5.12 一次
开发为 AP1，再用相同输出 ICC 的 LCMS2 浮点相对色度转换生成 sRGB；预览在
完整解拜耳后缩成半尺寸，不能称作原生 Bayer 四像元读取。完整输出与原 RT
独立两路基准比较，AP1 最大差为 0，sRGB 最大差 2.3842e-7。

“只读两次”指上述 RAW 传感器解码/开发阶段；导入复制、元数据读取、完整性
校验是文件 I/O，不声称操作系统只读取每个字节两遍。换相机校准属于新的输入
版本，不能把旧校准预览与新校准完整结果混合。

缓存容量与内存预算现可在设置中调整。下表的固定数值为最初默认值；
当前策略以[缓存设置](streaming-io-cache-settings.zh-CN.md)为准。

## 缓存层

| 数据 | 用途 | 保留与清理 |
| --- | --- | --- |
| RAW 原件及内容身份 | 恢复和首次完整开发 | 由项目保留，不属于可清理缓存 |
| half/full 开发结果 | sRGB 与 LUT 输入浮点数据 | 原子记录、跨读取者锁；不因 LRU 或容量自动删除 |
| 预览数组与缩略图 | 2048 短边预览及胶片条 | 可从保留的开发结果恢复；有效旧快照不会因程序升级自动重读 RAW |
| 显示成片 | 已固定照片、配方、曝光和显示条件的 A/B 图 | T7 上约 2 GiB LRU；同内容 PNG 去重，可由浮点数据重建 |
| 图像字节内存 | 提供显示资源 | 128 MiB 有界 LRU |
| 输入数组映射 | 供计算与邻图读取 | 512 MiB LRU；新预览为 float32，float64 科学参考不变 |
| 界面已准备画面 | 立即切图 | 估计解码后容量不超过 256 MiB，最多 8 组 |

RAW 阶段的 `ledger` 记录开发状态。已经提交的数据损坏、丢失或开发中断时明确
报错，需要恢复或显式建立新输入版本，不会静默第三次开发。程序升级可接纳
校准、ICC 和文件哈希均匹配的历史开发结果，而不是为新键重读原件。

图库恢复先读取索引、缩略图和数组头，不逐张读遍 RAW 原件。预览数组在第一次
使用前完整校验，之后使用不可变缓存及文件身份记录。完整导出仍校验原件身份
并逐像素、逐 ICC 读回成片。这里只描述应用管理的不可变数据，不承诺识别所有
绕过应用且伪造同一文件身份的外部修改。

## 显示与调度

显示缓存键包含输入身份、预览版本、完整配方、逐张输入曝光、显示目标、选点、
源资料与实现/渲染器版本。相同键的并发请求合并成一个计算；后台预取排在等待
中的当前画面之后。RAW 解码名额与显示渲染名额分开管理。

界面先复用已经准备好的画面；空闲时按顺序预取下一张和上一张，只使用已经
准备的预览，不为预取触发旧 RAW 升级。切图后取消过期的等待与界面回写；已开始
的后台帧可以完成并进入缓存，过期结果不会覆盖当前照片。未命中时显示当前照片
的缩略图及准备状态，不把上一张成片冒充当前结果。

预览返回内容寻址的 PNG URL，JSON 不再内嵌两张 base64 图像。保留正确 ICC 和
无损像素。交互预览不再每次额外解码 PNG 作读回检查；导出仍执行原有读回校验。
原生 WebKit 使用非持久数据存储，显示缓存文件、预览数组、RAW 阶段、临时文件
和导出均在配置的 T7，未连接时不回退内置盘。

## 验证

新增测试覆盖两阶段实际解码计数、重复导出、重启、并发读取者、旧数据接纳、
损坏阶段拒绝重读、显示缓存恢复/损坏/淘汰、缓存键变化、二进制像素/ICC 和
过期切图结果保护。完整应用测试执行：导入 → 调配方 → 两次导出 → 重启 →
再导出，实际 RAW 解码总计两次。

在本机 M2 Pro 上，用真实 R6 和 D850 预览进行浏览器界面验证：预热后的 8 次
交替切图中位约 32 ms（最终复测范围 31–71 ms），额外计算请求为 0；此前相同尺寸热计算约 1.2–1.3 s。
返回说明 JSON 约 77 KB，此前约 18–20 MiB。计时到两个动画帧后读取可见图像
状态，不是对所有硬件或首次未缓存画面的延迟保证，也不等同于原生窗口合成器
的专门测量。

本地证据：`artifacts/filmstrip-profile/profile.json`、`cache-switch-ui.json`、`cache-prefetch-ui.json` 和
`artifacts/raw-superpixel-final/dispatch-0b5a5cfc2cac454aa2e22f9c1753a46a/comparison.json`。
相机原件、缓存与个人路径不随源码发布。
