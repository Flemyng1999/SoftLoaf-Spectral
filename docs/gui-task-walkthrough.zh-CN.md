# 配方工作台的任务走查

本文保留早期设计／执行记录；5207 与相纸已接入计算，当前状态以[流程核查](5207-pipeline-audit.zh-CN.md)为准。


当前结构以用户后续复核为准：回到左侧固定流程和节点、中间输入／结果、
右侧当前节点参数。照片为辅助视图，胶片的感光／特性／染料数据收在节点
内切换。下面的照片工作台建议和初轮检查保留为过程记录，不是当前界面
要求；实际设计见[节点工作台](gui-design.zh-CN.md)。

本轮由普通 RAW 用户、光谱实验用户和交互设计师三个代理分别做认知走查。
它们阅读同一项目和原型，从各自任务推演操作。这是启发式分析，不是真实
用户访谈或可用性测试，也不能据此证明某个界面是最优解。

共同发现：第一版把“查看计算节点”当成主要任务，却没有把“制作并带走
一份配方”连接起来。保存只是会话状态，对照只固定一张节点曲线，照片
不随参数变化，生成终点不可执行。按钮存在不能作为任务完成的证据。

## 本轮选择

采用“配方工作台”。向导适合第一次填写资料，却不适合反复实验；纯节点
检查器适合研究程序内部，要求用户代管过多状态。配方工作台把完整配方
放在中心，试片用于观察，光谱用于解释，LUT 是冻结配方的交付结果。

原有 Apple 相册式的安静视觉和猫标保留。操作模型重新组织为：

```text
选一份完整配方 → 在内置试片上改一个条件 → 看结果与成因
→ 在相同输入上比较两份配方 → 命名保存 → 按使用用途导出
```

## 四种对象

| 对象 | 归属与保存范围 |
| --- | --- |
| 配方 | 胶片材料、胶片曝光偏移、成像终点、观看条件、显示外观、来源与版本 |
| 试片 | 内置 RGB 图像或色样、输入曝光、取样位置；不自动写入通用 LUT |
| 对照 | 一份完整配方快照；使用当前同一试片输入重新计算 A/B |
| 交付 | 冻结配方版本、输入输出约定、65³、包含显示与否、读回和抽样检查 |

“胶片曝光”写入配方，作用于非线性材料曝光阶段。“试片输入曝光”只校正
当前观察输入，并同等作用于 A/B。材料曝光锚点随校准数据冻结，不作为
普通创作滑块。三者不能共用一个含混的“曝光”概念。

## 对走查问题的设计回应

| 任务 | 第一版断点 | 本轮必须具备的行为 |
| --- | --- | --- |
| 不导入照片开始试用 | 只看到节点和单色曲线 | 打开完整 E100 配方和内置 RGB 试片，显示与配方一致的计算结果 |
| 胶片多曝光半挡 | 锚点命名含混，照片固定 | 直接 +0.5 EV，图像和同一取样的诊断更新；一次撤销恢复整份修改 |
| 换观看光源 | 不清楚什么应保持 | 胶片透射谱不变；观看光谱和颜色更新；明确说明适应参考 |
| 看懂变化 | 照片／光谱互斥，选节点改变上下文 | 结果与所选点的解释同屏；扩大光谱时仍保持试片、取样与版本身份 |
| 比较之前效果 | 固定曲线可混入不同试色 | 对照保存整份配方，每次换输入或取样都对 A/B 同样重算 |
| 5207 更换成像终点 | 两份隐藏的上游状态 | 同一配方保留共用胶片阶段，只切换数字化／相纸后段；换完整模板则新建独立对象 |
| 替换自定义数据 | 固定网格示意 JSON 缺完整保存 | 先验证数量、单位、波段和来源；失败保留原配方，成功后把完整数据纳入保存 |
| 保存并重新打开 | 只清除 dirty，自定义曲线被省略 | 实际命名 JSON 文件，保留参数、来源引用和完整自定义 SPD；打开时验证匹配 |
| 带到别处使用 | 内部 XYZ CUBE 容易被当作显示效果 | 先选择交付用途，说明 ACEScct 输入、是否包含 OpenDRT，并检查生成文件 |

## 验证范围

本轮接通已有 E100 float64 参考与实际 OCIO/OpenDRT，预览使用与 LUT 相同
的 RGB 光谱近似。内置图像先成为普通 AP1 RGB，再进入配方；不把 HSI
直接卷积结果用作预览却导出另一种 RGB 变换。用户不需要提供 HSI 或相机
光谱响应。

5207 数字化与光学放大保留草案编辑和状态设计。缺少对应引擎时不计算
假图像、不假装定标成功、不生成占位 LUT；提供回到上一份可计算配方的
实际路径。普通 RAW 开发也不在本轮实现范围，不能把文件名当成已解码结果。

新原型使用本机项目服务，避免把真实 API 和下载硬塞进仅用于展示的沙盒。
接口、数量、版本和导出条件见[工作台契约](gui-workbench-contract.md)。
最终记录应分别说明：代理发现了什么、原型实际通过了哪些任务、哪些任务
仍因缺少引擎或数据被阻断。数值测试和按钮点击都不能代替真实用户完成任务。

## 本轮执行记录（2026-10-26）

使用本机浏览器实际执行以下任务，并读取生成文件；不是让代理仅根据
界面文字宣布通过。

| 任务 | 已观察到的结果 |
| --- | --- |
| 无文件开始 | 默认 E100 和内置普通 RGB 试片得到真实图像；不要求 RAW、DCP 或 SSF |
| 多曝半挡与撤销 | 图像、入射谱及透射率更新；一次撤销后的解码图像像素与原图完全一致 |
| 更换观看光 | D50→D65 后胶片透射率绘图数据保持一致；观看结果更新 |
| 配方 A/B | 两侧同一色样的 AP1 数值一致；试片输入曝光 +0.5 EV 同时用于两侧，配方版本不变 |
| 自定义光源 | 缺少边界波段的输入被拒绝，原 D65 保留；完整六点合成 SPD 可导入、保存和重新打开 |
| 命名与重开 | JSON 名称、曝光、全部 SPD 点和来源引用保留；相同试片条件下重开后的图像像素完全一致；反复打开同 ID 文件不重复建库 |
| 5207 草案 | 同一负片切到相纸终点保留 +0.5 EV；列出正确的相纸节点和缺项；不显示 E100 图冒充结果，可恢复上一成功快照 |
| 完整效果导出 | 主下载为 ZIP，包含 CTF、材料 CUBE、配方、manifest 和 OpenDRT MIT 原文；下载后独立 OCIO 文件读取成功，CTF 不引用外部 LUT 文件 |
| 生成期间继续编辑 | 导出冻结 r1，当前配方成为 r2 后仍明确标识旧结果，不能把 r1 当成 r2 的完成状态 |
| 单显示 CUBE 失败 | 连续码值 96.9906%、8 位取整 97.4686%，界面显示失败且没有下载链接；选择新用途后不再显示上一个用途的下载 |

默认 E100/D50 完整效果包的独立构建样本检查为连续码值 99.0940%、
8 位取整 99.3671%。这是本次指定 RGB 样本集的插值检查；不是全域、
独立光谱场景或真实胶片准确性的保证。换配方后必须重新生成检查。

浏览器检查覆盖 1440×1000 浅色、1024×900 深色及 390×844 窄窗口，
未见横向溢出或应用控制台错误。桌面任务为主要验收对象，窄窗口仅做布局
冒烟检查，没有据此声称完整移动端可用性或无障碍合规。

计算与接口测试为 52 项；另有 5 项实际异步处理函数的回归测试，使用延迟
响应检查跨配方修改、保存期间继续编辑、导出等待修改提交、同版本号的指纹
碰撞，以及恢复成功快照而保留未完成修改。运行方式：

```sh
.venv/bin/python -m pytest -q
node --test tests/gui_workbench_state.test.cjs
```

代理复查发现的状态问题已通过上述回归及浏览器任务检查修正。仍未完成的
是 RAW/DCP 开发、5207 和相纸计算、任意材料替换、真实用户测试，以及
外部宿主软件对 CTF 的逐一兼容性验证。

## 用户复核后的修订

用户指出照片工作台虽然更好看，组织大量节点和光谱却比第一版复杂。
因此撤掉常驻照片和第二套材料面板：流程节点常驻侧栏，相关曲线归在
节点内，数值采样等放进精细编辑。代理的推演没有取代用户对主任务的判断。

这一轮也补齐了 E100 的真实源数据编辑。浏览器验证了感光通道倍率改变
图像、拖动更新采样值、撤销同步源曲线、完整材料保存／重开像素一致。
不相容的特性曲线因灰锚点无解被拒绝，原配方保留。编辑后的 R 感光通道
增加 5% 的配方已实际生成并下载 65³/CTF 包，本次构建样本连续码值检查
为 99.0730%，8 位取整为 99.3671%；这些不是胶片准确性数据。

后续用户要求彩负直接使用标准 APD。负片分支因此改为负片透射谱 →
APD 密度 → 固定标准负片至 ACES 变换与输出桥接，移除翻拍光源、相机
和设备定标。光学放大仍直接使用共用负片透射谱。APD 标准权重、覆盖、
归一化及标准输出版本尚未接入，负片继续明确显示草案。

新增状态回归覆盖未应用光谱阻止保存／导出，以及延迟文件读取与应用之间
的竞争，防止导入数据被旧提交清掉。导入文件的原始 SHA-256 与完整采样
一起保留，源曲线和计算结果分开显示。

最终本机检查为 69 项 Python 计算／接口测试和 8 项 JavaScript 状态回归。
节点布局另在 1440×1000 浅色和 1024×900 深色窗口检查，未见横向溢出或
应用控制台错误。实际点击节点只显示对应参数；APD 分支只有六个节点，
没有翻拍设置。源曲线单击只选点，拖动才改值；SVG 坐标转换经过实际
浏览器拖动检查，不依赖窗口中的固定像素位置。

```sh
node --test tests/gui_workbench_state.test.cjs tests/spectral_editor_state.test.cjs
```
