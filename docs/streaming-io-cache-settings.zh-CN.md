# 分块图像处理与缓存设置

2026-10-28，Issue #10。读取区域、处理区域、编码和读回校验分开实现，应用层只负责调度。

## 图像路径

`imaging` 管理区域来源、内存预算、浮点重采样、逐点渲染、量化和 PNG 行编码。
`exporting` 管理冻结配方、单张导出和批量文件包。`cache_settings` 管理机器设置、
缓存所有权、空间检查、统计、清理和位置切换。材料、色彩转换和相机校准继续由原模块负责。

预览与完整尺寸导出共用以下路径：

1. 从保留的数组或 TIFF 读取区域。完整 RAW 输出按区域独立映射，用完解除映射。
2. 用冻结的配方计算。Metal 每块不超过 65,536 像素；CPU float64 参考使用更小区域。
3. 区域量化后放入小的 RGB8 行带，交给 libpng。没有整张浮点输出数组。
4. PNG 逐行读回，检查像素 SHA-256、尺寸、ICC 和配方指纹。导出文件包另做 CRC 校验。
5. 单张成片通过校验后从工作目录原子切换为可下载结果；下载按 1 MiB 缓冲传输。

PNG 是无损 8-bit RGB，内嵌与 sRGB / Display P3 等目标匹配的 ICC。
计算使用线性 AP1/D60 或原始反射率，显示转换后才量化。预览沿用四舍五入到最近偶数；
照片导出沿用非负显示值的半入量化。曝光、观察者、白点、材料版本和显示设置保存在旁附元数据里。

当前计算逐点独立，因此不需要重叠边界。未来加入邻域或全图分析操作时，必须声明
支持半径或单独分析阶段，不能直接假定现有分块方式仍成立。

RAW 的两个开发阶段保持不变。half-size 开发后，两路预览按行重采样并写入外置浮点数组，
不为缩略图或切图再开发 RAW。兼容读取器的 AP1 → sRGB 浮点 ICC 交接、输出有效性检查
也按区域映射。全局重采样系数避免各行带单独取整造成接缝。

RT 自身仍按相机尺寸开发 RAW；这里没有把 RT 改为流式传感器解码器。RGB PNG/JPEG
入口仍有 16 MiB / 1200 万像素限制，保留有界的整张 RGB8 解码图，颜色浮点转换按区域进行。
内存预算不包括 RT、系统、驱动、基础光谱模型或上传请求本身。

## 设置

应用菜单“设置…”、⌘, 或侧栏“设置…”打开同一个窗口。设置属于这台机器，与配方无关。

| 项目 | 当前行为 |
| --- | --- |
| 显示缓存 | 可重建的配方结果、PNG 与索引，按 LRU 清理 |
| 保留数据 | RAW half/full 开发结果、浮点预览；普通清理不删除 |
| 自动磁盘容量 | 总容量的 1%，限制在 2–8 GiB，不随当前剩余空间反复变化 |
| 自定磁盘容量 | 1–512 GiB；当前生成和使用中的结果可暂时超过容量 |
| 关闭 | 不复用或写入持久显示索引；当前会话仍在 T7 使用最多约 8 组临时 A/B 图 |
| 自动内存 | 物理内存的 1/16，限制在 512–2048 MiB |
| 自定内存 | 256–8192 MiB；分配给输入映射、编码字节、界面画面和分块处理 |
| 空间预留 | 自动为总容量的 2%，限制在 2–16 GiB；可自定 0–256 GiB |

空间预留是写入准入检查，不是预先占用磁盘。新 RAW 开发按当前支持的最大相机图像
保守检查两路 TIFF 所需空间；已有开发结果直接复用。导出还检查成片与文件包的空间。
并行的外部程序仍可能耗尽磁盘，写入失败会报错，不能把预留值理解为系统配额。

更改位置只移动显示缓存，不移动原件、保留的 RAW 开发数据或预览输入。
目标必须在配置的外置卷，使用应用建立的专用子目录和所有权标记。
复制后逐文件核对 SHA-256，通过后才保存新设置；失败或停止时原位置仍有效。
可再次选择相同目录重试，原位置副本由“清理旧位置”显式清理。
未知文件不会被删除；正在生成预览时拒绝清理或迁移。不会向内置盘降级。

关闭持久缓存时，会话文件不进入持久索引。正常运行中限制临时结果数量，启动时只回收
有本应用标记、且所属进程已退出的旧会话；不能证明归属的文件保留。

## 验证

三条管线在 sRGB、Display P3 上与原完整 GPU 输出逐字节比较，块边界没有差异；
同时与 float64 科学参考比较，显示浮点值绝对误差限为 3e-4。
PNG 行编码另由 Pillow 独立解码检查像素、ICC 和指纹。
这验证实现与原科学模型一致，不新增材料实测准确性的结论。

同一份已保留的 Nikon D850 数据（8280 × 5512，45,639,360 像素），独立子进程测试：

| 方式 | 进程峰值内存 | 图像处理及校验耗时 |
| --- | --- | --- |
| 原整图浮点输出、整图量化和 Pillow 读回 | 2106.7 MiB | 11.91 s |
| 32 MiB 分块预算、行编码与行读回 | 268.1 MiB | 23.43 s |

分块测试在导出前已有约 265.7 MiB 的模型与运行时峰值，成片使用 788 块，最大区域
57,960 像素，RGB8 行带最大约 170 KiB；本次没有 RAW 解码。
新路径显著降低这一测试的峰值内存，但行 I/O、独立映射及编码增加了耗时。
不能将这组结果推广为所有相机、冷启动 RAW 解码或整机内存上限。

参考 SoftLoaf Negative 的缓存设置、分块规划和行写入架构，以及
[AlcedoStudio 固定版本](https://github.com/zidage/AlcedoStudio/tree/18c863702565e4be7cba5d889314b555b6fb6037)
的分层缓存和任务调度；未复制其他产品的私有代码或配置。libpng 由独立依赖提供，
当前本机开发构建使用 Homebrew 库，跨系统打包还需另行验证依赖兼容性。

完整 Application 导出入口另用同一 D850 保留数据执行：PNG、JSON 和 ZIP 均通过
校验，峰值 289.8 MiB，总耗时 22.20 s；用禁止启动 RAW 开发命令的检查确认
没有再次解码。其 PNG 像素 SHA-256 与独立分块测试完全相同。

最终回归为 Python 353 项、JavaScript 68 项和 CTest 2 项通过；后续缓存统计
并发读取的小调整另通过对应 9 项缓存测试。设置界面在 Chrome 的 1440×1000、
960×650 视口验证，原生 WKWebView 的 ⌘, 与文件夹选择器也已操作核对。
